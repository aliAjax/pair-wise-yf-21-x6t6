# 染线排产台 · 地毯修复工坊共用染槽调度

几家修复工坊共用染线槽，馆藏借展与私人订单常为同一色卡批次抢槽。本排产台把
**纹样档案 / 修复批次 / 材料色卡 / 槽位** 四类记录接起来，并在浏览器本地真实执行
排产、停机顺延、外协对账与旧数据升级（localStorage 持久化，可随时重置）。

## 核心规则（均由代码引擎执行）

排产引擎 `src/lib/scheduler.ts`

1. **同一槽位同一时段只容纳一个批次**：最小占用单位为「槽·日」，硬约束，绝不重叠。
2. **按加急顺序占位**：加急 > 普通；同级交期早优先，批次号兜底，排序稳定。
3. **容量满时保留交期并排队**：排不进的批次状态置为「排队待排」，`dueDay` 不变，
   容量释放后可一键补位/重排。
4. **染色类型不串槽**：植物染 / 矿物染 / 化学染只能进兼容槽位。
5. **染机停机/维护后顺延**：只释放「已排产未开染」批次的占用，并在剩余容量上按加急
   顺序顺延；**在染 / 已染好 / 已入库** 批次占用锁定不动，染好的照旧入库；仍排不进
   的继续排队、交期不变。
6. 工序状态机：已占槽 → 在染（此时占用转为锁定）→ 已染好 → 已入库，只前进不回退。

外协对账 `src/lib/reconcile.ts`

7. 回执只按**批次号**与本院记录对账。
8. 色卡批次或用量不一致、或查无此批次 → **留待处理**，不写工序、不改状态，等待人工
   采纳/驳回。
9. 晚到的重复回执（与已确认内容一致）→ 忽略。
10. 一致回执只向工序流水**追加**一条「已确认」；工序流水只增不改，**后到回执永远不能
    改写已确认工序**。

旧数据升级 `src/lib/migrate.ts`

11. 旧记录缺交期 → 补为**普通单**，给兜底交期并标注「交期待补」。
12. 旧记录缺槽位号 → 置为**待分配（排队）**，由排产引擎按剩余容量统一分配。
13. 旧记录完整保留（`source=legacy` 标记 + 迁移流水），缺失的关联档案/色卡也能打开查看。

## 界面

- 顶部指标：已占槽 / 在染 / 排队 / 超期风险 / 回执留待 等实时统计
- **槽位甘特图**：按槽×日展示占用条（加急/普通/旧档/锁定分色），停机窗口斜纹、超期黄框
- 排队队列条：容量满时保留交期排队，加急前置
- 停机控制面板：登记某槽 D 段停机并自动顺延、恢复后重新顺延、全量重排、补位
- 外协回执面板：录入回执即时对账，留待项可人工裁决
- 新建批次表单：选纹样档案与色卡（自动带染色类型与容量校验），建单即按加急排队
- 批次列表（排队/已占槽/在染/超期/旧档筛选 + 产地筛选）与批次详情（档案、色卡、
  只增不改的工序流水、关联回执）
- 纹样与色卡页、操作留痕日志

## 技术栈

React 19 + Vite 7 + TypeScript（strict）。排产/对账/迁移均为纯函数，位于 `src/lib/`。

## 本地运行

```bash
npm install
npm run dev        # http://localhost:62009
npm run build      # 类型检查通过的生产构建
```

初始数据在载入时真实跑一遍：旧档升级 → 首版加急排产 → 5 张外协回执逐条对账
（含一致、晚到重复、色卡批次不一致、用量不一致、查无批次五种情形）。
